# Скилл: eLIBRARY Source Collector

## Что это за проект

Локальный веб-инструмент (Flask), который превращает сохранённые из браузера HTML-страницы
результатов поиска [eLIBRARY.RU](https://elibrary.ru/) («Список публикаций», до 10 страниц × 100 записей)
и карточки статей в:
- таблицу источников (CSV + XLSX): название, авторы, журнал, год, том/номер, страницы,
  цитирования, цитирования по ядру РИНЦ, открытый доступ, аннотации/ключевые слова;
- саммари массива: годы, журналы, топ-15 по цитированиям, выводы.

Целевая аудитория — исследователи и аналитики, делающие литературные обзоры по русскоязычным источникам.

## Структура репозитория

```
app.py                   # веб-приложение Flask; маршруты /, /process (с повторной догрузкой по stamp), /rebuild, /download/<name>
templates/
  index.html             # стартовый экран: инструкция + загрузка файлов
  result.html            # результат: плитки, годы, топ-15, журналы, дайджест аннотаций, таблица, порядок вывода, «Дополнить набор», скачивание
  error.html             # ошибки обработки
scripts/
  elib_list_parser.py    # ядро: парсер списков и карточек; write_csv/write_xlsx; CLI-режим
  elib_summary.py        # compute_summary() и format_markdown(); CLI-режим
  elib_digest.py         # дайджест по аннотациям: суть статей (маркеры Предмет/Цели/Результаты/Выводы), ссылки, тематика
  dev/                   # диагностические скрипты (не часть MVP)
data/
  raw/                   # сырые страницы eLIBRARY — НЕ публиковать (данные сессии!)
  processed/             # результаты: sources_<stamp>_<sort>.csv/.xlsx, summary_<stamp>.md, digest_<stamp>.md
tmp/                     # загрузки пользователей — НЕ публиковать
docs/project-description.md  # описание проекта (проблема/пользователь/функция/MVP/технологии)
screenshots/             # серия скриншотов по разделам сценария (01-search … 07-review + README-screenshots.md)
drafts/                  # локальная папка: обзоры литературы субагента (review_<stamp>.md, в git не входит)
skills/                  # опубликованные копии скиллов для установки в свой проект
```

Ключевые факты о входных данных, без которых легко всё сломать:
- страницы списков — кодировка **смешанная** (UTF-8 + cp1251 + двойное кодирование);
  везде используется `decode_bytes()` + `fix_mojibake()` из `scripts/elib_list_parser.py`;
- карточка статьи узнаётся по наличию «КЛЮЧЕВЫЕ СЛОВА:» + «АННОТАЦИЯ:»;
- цитирования по ядру РИНЦ есть **только в карточках** — в списке публикаций этого поля нет;
- встречаются записи без страниц и без авторов (особые ветки парсера уже написаны — не удаляйте резервные пути).

## Запуск и проверка

```bash
pip install flask openpyxl
python app.py            # → http://127.0.0.1:5000
```

Быстрая проверка без браузера:
```bash
curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:5000/            # ожидается 200
```

Тестовые данные: у автора проекта есть образцы в `data/raw/probe/` (в git не попадают из-за
приватности). Если их нет локально — сохраните 1–2 страницы «Список публикаций» eLIBRARY сами
(Ctrl+S → HTML). Важно: файлы с кириллическими именами в curl-запросах (-F) ломаются в Git Bash —
для тестов скопируйте их под ASCII-именами.

## Типовые изменения

- **Новое поле таблицы**: правки в `scripts/elib_list_parser.py` (список `HEADERS`, разбор поля),
  затем колонка в `templates/result.html` (таблица результата). CSV/XLSX обновляются автоматически
  (`write_csv`/`write_xlsx` пишут по `HEADERS`).
- **Новая статистика в саммари**: `compute_summary()` в `scripts/elib_summary.py`;
  текст вывода — `format_markdown()`; на экране — карточка в `result.html` (одни и те же данные).
- **Визуальные правки** — только `templates/*.html`, стили инлайном в каждом шаблоне (никакой сборки).
- **Изменение порядка вывода** — словари `SORTS`/`SORT_LABELS` и `sort_rows()` в `app.py`.

## Порядок проверки после изменений

1. Запустить `python app.py`; проверить код 200 на `/`.
2. Прогнать curl-POST с тестовыми файлами (см. выше) — ожидаются: 1000 записей, 393 журнала,
   4 карточки применены.
3. Проверить `/rebuild?stamp=<из ответа>&sort=citations` — код 200; первая строка CSV —
   «СТАВРОПОЛЬСКИЙ ГОСУДАРСТВЕННЫЙ АГРАРНЫЙ УНИВЕРСИТЕТ…» (93 цит.).
4. Проверить скачивание: `/download/sources_<stamp>_citations.csv` → 200; чужое имя файла → 404.
5. Убедиться, что `data/processed/` не переполнен старыми прогонами, а `tmp/` в `.gitignore`.

## Публикация изменений в GitHub

Репозиторий опубликован: https://github.com/IVGrishina/elibrary-source-collector (public, ветка main).

1. Проверить `.gitignore`: `data/`, `tmp/`, `drafts/`, `__pycache__/`, `.claude/` не публикуются;
   рабочий протокол в корне проекта ( файл `2026-11-16-…протокол.md`) не добавлять в коммит.
2. Прогнать полный цикл проверки (раздел выше).
3. `git add` только целевых файлов → commit → `git push origin main`
   (gh CLI вызывать как `"/c/Program Files/GitHub CLI/gh.exe"` — в bash PATH его нет).
4. Обновлённые скриншоты живут в `screenshots/<раздел>/` и вставлены в README по образцу
   `![описание](screenshots/01-search/03-search-elibrary.png)`; после push проверить
   статус 200 у raw-URL: `https://raw.githubusercontent.com/IVGrishina/elibrary-source-collector/main/<путь>`.
5. Проверить страницу в режиме инкогнито (у автора — только HTTP-проверки: браузерной автоматизации в системе нет).

⚠️ Никогда не публикуйте `data/raw/` или содержимое загрузок — внутри данные сессии eLIBRARY
пользователя (имя, SPIN-код, IP).

## Связанные скиллы

- `elibrary-literature-review` — обзор литературы по дайджесту аннотаций; результат —
  `drafts/review_<stamp>.md`. Оба скилла публикуются в каталоге `skills/` репозитория:
  обновляйте сначала рабочие копии в `.claude/skills/`, затем копируйте в `skills/<имя>/SKILL.md`
  той же правкой.

## Субагент-райтер

Написание обзора лучше поручать субагенту-райтеру (в окружении автора — `writer-reg-econ`,
Agent tool), передав ему путь к свежему `digest_*.md` и разделы скилла `elibrary-literature-review`
как инструкцию. Без субагента скилл исполняется напрямую по его шагам.
